# 수박게임 Unity 개발 기획서

버전 0.2 · 2026-11-12 · WebGL 세로형 · 싱글 플레이

## 1. 게임 개요

플레이어는 상자 위에서 과일을 좌우로 조준하고 하나씩 떨어뜨린다. 같은 종류의 과일 두 개가 만나면 한 단계 큰 과일로 합쳐진다. 한정된 공간에서 다음 과일을 보고 배치하며, 상자가 넘치기 전까지 점수를 쌓는다. 수박 두 개를 합치면 큰 공간을 되찾아 한 판을 이어갈 수 있다.

| 항목 | MVP 범위 |
|---|---|
| 플랫폼 | Unity WebGL, PC·모바일 브라우저, 세로 화면, 마우스·터치 조작 |
| 프로젝트 | Unity 6.0.80f1 기준, 2D 물리, uGUI·TMP, New Input System |
| 모드 | 오프라인 무한 점수 도전 |
| 화면 | 타이틀, 플레이, 일시정지, 결과 |
| 저장 | 최고 점수, BGM·효과음·진동 설정 |
| 후속 후보 | 튜토리얼 미션, 랭킹, 일일 시드, 이어하기 |

### 플레이 흐름

1. 타이틀에서 시작을 누르면 빈 상자와 점수 0으로 시작한다.
2. 현재 과일과 다음 과일을 확인한다.
3. 화면을 누르고 좌우로 움직인 뒤 손을 떼어 과일을 떨어뜨린다.
4. 기존 과일과 부딪히고 굴러가며, 같은 종류가 만나면 합쳐진다.
5. 다음 과일로 조준을 반복한다. 이전 과일의 이동과 합체는 계속 진행된다.
6. 넘침 조건이 충족되면 최종 점수와 최고 점수를 보여준다.

## 2. 게임 규칙

### 2.1 등장과 조작

- 드롭 가능한 과일은 체리, 딸기, 포도, 데코폰(한라봉), 감이다. 기본 확률은 각각 **20%**이며 연속 중복을 허용한다. 한 판을 시작할 때 현재 과일과 NEXT를 각각 뽑는다.
- 조준은 상자 위 고정 높이에서 가로 방향으로만 이동한다. 과일 반지름만큼 벽 안쪽으로 조준 범위를 제한한다. 처음에는 중앙에서, 이후에는 직전 드롭 위치에서 다음 과일의 반지름에 맞춰 조준 위치를 잡는다.
- 플레이 입력 영역 안에서 시작한 터치 하나만 추적한다. 터치 위치의 월드 X를 사용하고, 움직임 없이 손을 떼면 해당 위치에 바로 드롭한다. 영역 밖에서 손을 떼면 마지막 화면 좌표를 벽 안쪽으로 제한해 사용한다.
- HUD 버튼 위에서 시작한 터치, 두 번째 손가락, 취소된 터치는 드롭을 발생시키지 않는다. 드롭 대기 시간 중에 시작한 입력도 버린다. 에디터의 마우스 클릭과 드래그에는 같은 규칙을 적용한다.
- 드롭 직후 NEXT를 현재 과일로 넘기고, 새 NEXT를 한 번 뽑는다. 드롭 간 최소 간격은 **0.45초**다. 대기 중인 과일의 물리는 드롭이 확정되는 순간 활성화한다.
- 조준 높이의 생성 위치가 기존 과일에 막히면 드롭을 보류하고 조준 표시를 경고색으로 바꾼다. 현재 과일과 NEXT는 그대로 표시한다.

### 2.2 진화와 점수

동일 단계 과일 두 개가 접촉하면 다음 단계 과일 하나를 생성한다. 서로 다른 단계는 물리 충돌만 처리한다. 드롭 자체는 0점이며, 연쇄 합체는 아래 점수를 각각 더한다.

| 단계 | 접촉하는 과일 2개 | 합체 결과 | 획득 점수 | 직접 드롭 |
|---:|---|---|---:|:---:|
| 1 | 체리 | 딸기 | 1 | ✓ |
| 2 | 딸기 | 포도 | 3 | ✓ |
| 3 | 포도 | 데코폰 | 6 | ✓ |
| 4 | 데코폰 | 감 | 10 | ✓ |
| 5 | 감 | 사과 | 15 | ✓ |
| 6 | 사과 | 배 | 21 | |
| 7 | 배 | 복숭아 | 28 | |
| 8 | 복숭아 | 파인애플 | 36 | |
| 9 | 파인애플 | 멜론 | 45 | |
| 10 | 멜론 | 수박 | 55 | |
| 11 | 수박 | 두 개 모두 제거 | 66 | |

- 합체 위치는 두 과일 중심의 중점이다. 새 콜라이더가 벽이나 바닥을 뚫지 않도록 과일 반지름에 맞춰 위치를 보정한다.
- 한 과일은 한 번의 합체에만 소비된다. 같은 물리 스텝에 같은 과일이 여러 후보에 포함되면 접촉 후보를 과일 ID 쌍으로 정렬하고 먼저 처리된 유효 쌍만 소비한다.
- 같은 물리 스텝에서 생성된 과일은 다음 물리 스텝부터 합체 후보가 된다. 겹친 상태에서 생성되는 경우도 검출할 수 있도록 충돌 진입과 지속 접촉을 후보로 등록하고 중복 쌍을 제거한다.
- 수박 두 개가 만나면 두 개를 제거하고 66점을 더한다. 결과 과일 없이 제거 연출을 재생하고 플레이는 계속된다.

### 2.3 넘침과 종료

- 양옆 벽의 상단에 위험선을 둔다. 직접 떨어뜨린 과일은 다른 과일이나 상자에 처음 충돌한 뒤부터 검사한다. 합체로 생성된 과일은 생성 직후부터 검사한다.
- 각 과일의 `Collider2D.bounds.max.y`가 위험선보다 높을 때 해당 과일의 타이머를 누적한다. **동일한 과일이 1.0초 연속** 기준을 초과하면 종료한다. 선 이하로 내려오거나 합체로 제거되면 해당 타이머를 초기화한다.
- 스텝마다 합체와 점수 반영을 먼저 처리한 뒤, 남은 과일의 넘침을 검사한다. 양쪽 벽을 타고 완전히 빠져나가는 경우에는 별도 이탈 영역에서 종료한다. 이탈 영역은 화면 가장자리 바깥과 상자 바닥 아래에 두고, 판정 대상은 첫 충돌을 마친 과일과 합체 과일로 한정한다.
- 위험선 위에 판정 대상 과일이 있으면 선과 해당 과일을 강조한다. 어느 과일이든 1초에 도달하면 드롭 입력과 물리를 멈추고, 점수를 확정한 뒤 결과 패널을 띄운다.

## 3. 화면 구성

### 3.1 타이틀

| 위치 | 요소 | 동작 |
|---|---|---|
| 중앙 상단 | 게임 로고 | 과일 일러스트와 제목 |
| 중앙 | 최고 점수 | 저장된 최고 점수 표시, 첫 실행은 0점 |
| 중앙 하단 | 시작 | 새 판 생성 |
| 우측 상단 | 설정 | BGM·효과음·진동 토글과 닫기 버튼 |
| 하단 | 조작 안내 | “좌우로 움직이고 손을 떼면 과일이 떨어져요.” |

### 3.2 플레이 화면

기준 해상도는 **1080 × 1920**이다. 아래 Y 범위는 9:16 세이프 에어리어 안에서 위부터 내려가는 배치 비율이다. 물리 보드와 HUD의 실제 배치는 기기 비율에 맞춰 조정한다.

| 영역 | Y 범위 | 구성 |
|---|---|---|
| 상단 HUD | 0–14% | 좌측 현재 점수와 최고 점수, 우측 NEXT 카드와 일시정지 버튼 |
| 조준 영역 | 14–27% | 현재 과일과 세로 조준선. 드롭 대기 중에는 조준선을 약하게 표시 |
| 상자 | 27–85% | 벽, 바닥, 과일, 위험선. 상자 안과 바로 위 영역에서 조준 입력 |
| 진화 순서 | 85–100% | 왼쪽부터 작은 과일 → 큰 과일. 폭이 좁으면 두 줄로 접고 화살표로 순서를 연결 |

- 현재 과일은 드롭 위치에 표시하고 NEXT 과일은 HUD의 고정 카드에 표시한다. 과일 아이콘은 실제 크기 비율 대신 카드 안에 맞춰 그린다.
- 위험선은 평소 옅게 두고 넘침 타이머가 동작할 때 색과 밝기를 바꾼다. 초과 과일의 외곽선도 함께 바꿔 색상 외의 정보로 상태를 전달한다.
- 조준선은 과일 중심에서 아래쪽으로 향한다. 다른 과일과 겹치는 부분은 흐리게 하여 실제 배치를 가리지 않도록 한다.
- HUD는 `Screen.safeArea` 안에 배치한다. 상자 월드 크기는 고정하고, 직교 카메라와 UI 배치로 9:16, 9:19.5, 9:20에서 HUD·상자·진화 순서가 겹치지 않게 맞춘다.

### 3.3 일시정지와 결과

| 화면 | 표시 내용 | 버튼과 동작 |
|---|---|---|
| 일시정지 | 보드 위 반투명 배경, 일시정지 제목 | **계속하기**로 복귀, **다시 시작**과 **타이틀**은 확인 후 현재 판 종료 |
| 결과 | 최종 점수, 최고 점수, 신기록 여부 | **다시 하기**로 빈 상자에서 즉시 재시작, **타이틀**로 복귀 |

- 브라우저 탭이 숨겨지거나 포커스를 잃으면 플레이를 일시정지한다. 복귀 시 일시정지 화면에서 재개한다. 일시정지 중 물리와 드롭·넘침 타이머를 함께 멈춘다.
- 오버레이가 뜨면 추적 중인 터치를 취소한다. 패널을 닫는 입력이 보드에 전달되지 않도록 하고, 새 터치부터 조준을 허용한다.
- 최고 점수는 게임 오버에서 기존 기록을 초과했을 때 저장한다. 재도전 시 과일, 합체 후보, 타이머, 조준 입력과 현재 점수를 초기화한다.

## 4. Unity 구현 설계

### 4.1 씬과 컴포넌트

| 구성 | 책임 |
|---|---|
| `TitleScene` | 시작, 설정, 저장된 최고 점수 표시 |
| `GameScene` | 카메라, 상자, 물리 과일, HUD, 오버레이 |
| `GameSession` | 상태 전환, 점수 확정, 재시작 |
| `DropController` | 포인터 소유권, 화면→월드 X 변환, 조준과 드롭 |
| `FruitSpawner` | 현재·NEXT 추첨, 과일 생성·제거 |
| `FruitActor` | 과일 ID·단계·첫 충돌 상태, 물리 컴포넌트, 접촉 보고 |
| `MergeResolver` | 후보 쌍 중복 제거, 합체 처리, 합체 이벤트 발행 |
| `OverflowDetector` | 과일별 넘침 타이머와 이탈 판정 |
| `GameHud` | 점수·NEXT·경고·패널 갱신 |
| `LocalSave` | WebGL `PlayerPrefs`(IndexedDB)에 최고 점수와 설정 저장 |

세션 상태는 `Ready → Playing ↔ Paused → GameOver`로 관리한다. `GameOver → Ready`로 재시작할 수 있다. 드롭 대기 시간은 `Playing` 안에서 별도로 관리하므로, 드롭을 기다리는 동안에도 이미 상자 안의 과일은 계속 굴러가고 합쳐진다.

### 4.2 데이터 구성

| 데이터 | 필드 |
|---|---|
| `FruitDefinition` | 단계, 표시 이름, 스프라이트, 반지름, 질량, 합체 점수, 드롭 가중치 |
| `GameRuleConfig` | 단계 순서, 드롭 간격, 위험선 높이, 넘침 유예, 보드 크기, 조준 높이 |
| 런타임 세션 | 상태, 현재 과일, NEXT, 현재 점수, 과일별 넘침 타이머 |
| 브라우저 저장 | 최고 점수, BGM, 효과음, 진동. 브라우저 데이터 삭제·시크릿 모드에서는 유지되지 않을 수 있음 |

과일 정의와 룰 설정은 `ScriptableObject`로 작성한다. 편집기에서 단계 1~11의 중복·누락, 반지름 증가 여부, 드롭 가중치 합계와 양수 가중치 범위를 확인한다. 합체 점수는 **소비되는 단계**의 설정값을 읽는다.

### 4.3 물리 초기값

| 항목 | 초기값 |
|---|---|
| 보드 안쪽 너비 / 위험선 높이 | 너비 8 유닛 / 바닥에서 10 유닛 |
| 조준 중심 높이 | 위험선에서 2 유닛 위 |
| 과일 반지름 1~11단계 | 0.28 / 0.36 / 0.46 / 0.56 / 0.66 / 0.80 / 0.95 / 1.12 / 1.32 / 1.56 / 1.85 유닛 |
| 콜라이더 | 과일 `CircleCollider2D`, 벽·바닥 `BoxCollider2D` |
| 물리 재질 | 마찰 0.3, 반발 0.05부터 조정 |
| 고정 물리 간격 | 0.02초 |
| 강체 | 활성 과일 `Rigidbody2D Dynamic`, 중력 스케일 1.0, 회전 허용 |
| 질량 | 단계별 값 사용. 초안은 반지름 제곱에 비례하도록 설정 |

물리 콜백에서는 충돌 정보를 수집한다. 다음 `FixedUpdate`에서 직전 시뮬레이션 스텝의 후보를 일괄 처리한 뒤 넘침과 이탈을 검사한다. 소비된 과일은 즉시 합체 후보에서 제외하고 충돌을 비활성화한다. 새 과일은 원래 두 과일의 평균 선속도를 초기값으로 사용하고, 과하게 튀는 경우 초기 속도 상한을 조정한다. 드롭 시작 높이와 작은 과일의 크기 때문에 충돌 누락이 보이면 해당 과일의 연속 충돌 검출을 적용한다.

## 5. 아트와 피드백

| 이벤트 | 시각 | 소리·진동 |
|---|---|---|
| 조준 | 과일 미리보기와 조준선 이동 | 없음 |
| 드롭 | 미리보기가 물리 과일로 전환 | 짧은 드롭음 |
| 합체 | 작은 파티클, 새 과일 팝 연출, 점수 갱신 | 단계에 따라 다른 피치 |
| 수박 두 개 제거 | 수박 위치에 큰 파티클과 +66 표시 | 전용 효과음, 설정이 켜져 있으면 짧은 진동 |
| 넘침 | 위험선과 해당 과일 외곽선 강조 | 경고 진입 시 1회 효과음 |
| 종료 | 상자 정지 후 결과 패널 등장 | 종료음 |

- 과일은 색뿐 아니라 실루엣과 꼭지·잎 모양으로 구분한다. 특히 데코폰과 감은 색이 비슷하므로 형태 차이를 크게 둔다.
- 크기 변화 연출은 자식 스프라이트에 적용한다. 물리 콜라이더는 생성 즉시 해당 단계 크기로 둔다.
- 아트 목록은 과일 11종, 상자와 배경, 로고, UI 버튼과 아이콘, 합체 파티클, 드롭·합체·경고·종료 효과음이다.

## 6. 구현 순서와 완료 기준

| 단계 | 산출물 | 완료 기준 |
|---|---|---|
| 1. 물리 프로토타입 | 상자, 조준, 낙하, 11단계 합체 | 동일 과일만 합체하며 수박 두 개까지 처리 |
| 2. 한 판 완성 | 추첨, NEXT, 점수, 넘침, 재시작 | 빈 상자에서 결과와 재도전까지 한 흐름으로 동작 |
| 3. 화면과 피드백 | 타이틀·HUD·일시정지·결과, 아트·효과음 | 터치와 에디터 마우스로 한 판 완료 |
| 4. 브라우저 검수 | 비율별 레이아웃, 물리 튜닝, IndexedDB 저장 검증 | 최신 Chrome·Edge·Firefox·Safari와 iOS Safari 15+·Android Chrome 58+에서 아래 시나리오 통과 |

### 검수 시나리오

| 상황 | 기대 결과 |
|---|---|
| 체리 두 개 접촉 후 만들어진 딸기가 기존 딸기와 접촉 | 포도 1개가 남고 총 4점 획득 |
| 같은 과일 3개가 동시에 접촉 | 2개만 소비되고 점수가 한 번 반영 |
| 수박 두 개가 접촉 | 두 개 제거, +66점, 플레이 계속 |
| 대기 과일 및 첫 충돌 전 과일이 선 위에 있음 | 넘침 타이머가 시작되지 않음 |
| 과일이 0.5초 튀었다가 내려옴 | 게임 계속, 해당 타이머 초기화 |
| 과일 A가 0.6초 초과 후 내려오고 B가 0.6초 초과 | 두 과일의 시간이 합산되지 않음 |
| 동일 과일이 1초 연속 위험선 초과 | 결과 패널 한 번 표시, 점수 확정 |
| 타이머 만료 스텝에서 초과 과일이 합체로 소비됨 | 새 과일 기준으로 검사하며 기존 타이머는 승계하지 않음 |
| 연타, 멀티터치, 앱 전환, 패널 닫기 | 의도치 않은 낙하·중복 추첨 없음 |
| 조준 위치에 기존 과일이 겹친 상태에서 드롭 시도 | 드롭 보류, 현재 과일·NEXT 유지 |
| 신기록 달성 후 재실행 및 재도전 | 최고 기록 유지, 새 판 점수 0과 빈 상자 |
| 노치가 있는 9:19.5·9:20 화면 | 버튼이 가려지지 않고 상자 양쪽 벽과 바닥이 보임 |
| 넓은 데스크톱 브라우저와 창 크기 변경 | 중앙 9:16 프레임을 유지하고 UI와 보드가 겹치지 않음 |
| 탭 전환·포커스 상실 후 복귀 | 자동 일시정지되며 사용자가 계속하기 전까지 물리와 타이머가 멈춤 |
| 새로고침 및 브라우저 재실행 | IndexedDB를 사용할 수 있으면 최고 점수와 설정이 유지됨 |

### WebGL 배포 기준

- WebGL 2와 WebAssembly를 사용하고 멀티스레딩은 비활성화한다.
- 빌드 압축은 Gzip과 Decompression Fallback을 사용하며, 빌드는 `file://`이 아닌 HTTP(S) 서버에서 실행한다.
- WebGL 템플릿은 게임 Canvas의 9:16 비율, 모바일 Safe Area, 로딩 진행률, 게임 영역의 브라우저 스크롤·확대 방지를 담당한다.
- 진동은 `navigator.vibrate` 지원 브라우저에서만 실행하고 미지원 환경에서는 무시한다.

## 7. 원작 참고와 튜닝 기준

원작에서 가져온 규칙은 좌우 조준과 드롭, 동일 과일의 진화, 11단계 순서와 합체 점수, 수박 두 개의 제거, 상자 넘침 시 종료다. 균등 추첨, 0.45초 드롭 간격, 1초 넘침 유예, 보드 치수와 물리 수치는 이 모작의 초기값이다. 첫 플레이테스트에서는 **과일이 너무 쉽게 튀는지**, **상자가 찼을 때 종료 이유가 보이는지**, **NEXT를 보고 배치할 여유가 있는지**를 기준으로 값을 조정한다.
